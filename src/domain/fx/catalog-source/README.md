# FTMO public catalog capture

Source: https://ftmo.com/en/symbols/ and https://ftmo.com/wp-json/ftmo/symbols.
Capture identifier `ftmo-public-symbols-global-2026-10-07`; capture date 2026-10-07 (Europe/Athens), request timestamp 2026-10-06T21:25:25 UTC. The complete response is retained verbatim alongside response headers, public table code, page HTML, route inventory, and official trading-update evidence. `capture-manifest.json` records request filters, observed counts, and source checksums. Counts describe this capture, not future catalog completeness. Normal use and tests load local data without a catalog request. Runtime uses `runtime-symbols.json`, a projection of required fields reproduced offline with `node scripts/project-catalog-source.mjs`; a test verifies every active projected contract against the complete raw capture.

`catalog.ts` filters active global records and categorizes Cash CFD once into indices or commodities; category slices use `buildInstrumentCatalog(categories)`. The active categories are forex (including Exotics), metals, indices, all eleven energy/soft commodities, crypto CFDs, and equities CFDs from this snapshot. Contract size, profit/margin currency, digits, and source movement unit are source fields. Forex base currency comes from its slash symbol; metal base identifies the metal. Nonforex instruments have no base currency for conversion; margin currency must not be substituted for profit currency.

Digits indicate display precision. No independently sourced execution tick-size field exists in this endpoint. Source nonforex movement unit is 1. Existing XAUUSD/XAGUSD retain the app's .01 pip convention for adjustments/manual pip-value compatibility. Existing US100 and US30 canonical names, lot defaults, and whole-point adjustment rounding remain compatible; `.cash` resolves to these same old keys. New cash symbols preserve `.cash`. New instrument adjustments use source digits; copied source price text retains its original precision.

## Volume-rule policy and limitation

The endpoint provides no minimum volume or volume step. Maximum volumes are not minimum/step evidence. Defaults are explicitly marked `compatibility-default`: .01 minimum/step for forex and metals, .1 for indices, and .01 for crypto/equity/commodity categories unless historical evidence applies. Only the old dynamic forex, XAUUSD/XAGUSD, US100/US30 defaults were established app behavior; applying category defaults elsewhere is a documented compatibility policy, **not a verified FTMO platform/account lot specification**. User lot-only overrides remain authoritative. Obtain a platform symbol-specification export to validate current account/platform minimums and steps.

The official 19 September 2024 update states that V, COCOA.c, COFFEE.c, SOYBEAN.c, WHEAT.c and CORN.c minimum and step changed to 1 effective 28 September 2024. These defaults are marked `historical-official`, not current account verification. The English article misspells COFFEE as COFEE; the current response provides the canonical spelling. Source metals XPD/XPT contract size 100 matches that update. The 27 August 2026 update provides recent crypto precision evidence.

## Alias policy

Match exact supported symbols/aliases first, case-insensitively; preserve meaningful punctuation. Only `.pro`, `.raw`, `.std`, `.m`, `_pro`, `_raw`, `_std` account decorations are stripped. Unsupported names return no canonical symbol and cannot obtain a generic forex contract. Valid currency pairs outside the snapshot keep dynamic forex compatibility.

The raw source incorrectly assigns nikkei/nk225 aliases to HK50.cash. Runtime suppresses them there and curates them for JP225.cash. The raw anomaly is unchanged in the snapshot. Legacy gold, silver, Nasdaq and Dow aliases remain. Short aliases need a symbol declaration or adjacent trade direction in imported prose. All equity aliases require that context or a leading stock marker (`$` or `#`), so ordinary words such as ARM and SNOW do not become instruments. Explicit declarations take precedence over incidental ticker mentions; unsupported declarations fail rather than selecting a different instrument. Equity signal-relative adjustments are capped at 5/10/20 displayed price increments for subtle/normal/strong strength, with the existing stop-distance ratio and structure/risk/reward guards. Fixed adjustments retain source movement units. Partial duplicate override keys merge during canonicalization, preserving nonconflicting configured fields.

## Commodity application policy

Commodity contracts keep source movement unit 1 and source price digits (energy 3, cocoa 1, other agriculture 2). Canonical `.cash` and `.c` suffixes remain intrinsic. WTI, Brent, natural gas, heating oil and bare commodity names resolve to their supported catalog instruments; only known account decorations are removable. Multiword aliases are matched as complete phrases without matching an unsupported dotted suffix.

Signal-relative commodity adjustments cap subtle/normal/strong movement at 1/2/3 quoted precision units (`10^-digits`), additionally bounded by the existing stop-distance ratio. This is application adjustment policy, not evidence of an execution tick. Explicit fixed-pips settings still use the instrument movement unit. All candidates retain existing price-structure, actual-risk and reward-ratio guards; rejected candidates fall back to the original result.

All commodity profit currencies in this snapshot are USD. USD accounts use exact contract valuation; EUR accounts use the existing configured/live EURUSD route. This route requires a successfully fetched rate or an explicitly entered/confirmed manual rate; the untouched initial example is not reliable conversion input. Explicit valid legacy stored rates remain usable when a refresh fails. Other account currencies at public domain boundaries require reliable conversion or a manual pip value; no commodity is allowed a generic forex specification.
